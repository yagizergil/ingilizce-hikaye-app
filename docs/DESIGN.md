# Design System — İngilizce Hikaye

This document catalogs the design tokens (`src/theme/tokens/`) and UI kit
(`src/components/ui/`) built for this app's second, approved design pass.
It replaces the first attempt entirely — that pass only changed color
tokens without changing the screens' character; this one is built strictly
from `mockups/*.html`, which are a **specification, not inspiration**.
Every value below is copied from a mockup, not invented or "improved."

Character: **C's typographic contrast + asymmetric grid, disciplined by
B's restraint** — a strong Fraunces/Plex Mono personality, but a single
warm-neutral palette with one accent used only for status/progress, no
cards, hairline dividers only. See `docs/ART_DIRECTION.md` for the full
three-direction comparison and the reasoning behind this combination.

## Fonts — three families, no separate UI sans

| Family | Role | Weights loaded |
|---|---|---|
| **Fraunces** | Headings, book/chapter titles | 500 (medium), 600 (semibold), 500 italic |
| **Literata** | Reading text (reader body, reading-surface chrome) | 400, 400 italic |
| **IBM Plex Mono** | *Everything else* — metadata, labels, stat numbers, nav, badges, buttons | 400, 500 |

There is deliberately no fourth "UI sans-serif" family. Plex Mono carries
all small UI text that would normally go to a grotesk sans — this is a
locked product decision, not an oversight.

Bundled via `expo-font` + `@expo-google-fonts/{fraunces,literata,ibm-plex-mono}`,
loaded in `app/_layout.tsx`'s `useFonts()` gate before any screen renders.

## Color (`src/theme/tokens/colors.ts`)

Warm neutral palette, one accent, three themes (`light` mockup-specified,
`sepia`/`dark` derived — see in-file comments for the exact derivation
reasoning per value).

| Role | Light |
|---|---|
| `bg.primary` | `#FAF8F4` |
| `bg.surface` | `#FFFFFF` |
| `text.primary` | `#1E1C19` |
| `text.secondary` / `text.tertiary` | `#8A8378` |
| `text.reading` | `#241F19` (reader surface only — see discrepancy note in the file) |
| `text.inverse` | `#FAF8F4` (text on an ink-filled surface, e.g. the CTA button) |
| `border.hairline` | `#E7E2D8` (the *only* divider color anywhere) |
| `border.strong` | `#1E1C19` (badge borders, reuses `text.primary`) |
| `accent` | `#A6572E` (muted terracotta/clay) |
| `accentMuted` / `secondaryMuted` / `overlay` | derived, documented per-value in the file |

**Accent discipline: `accent` is status/progress-only, never decorative.**
It appears in exactly four places across the whole app: the continue-reading
progress bar fill, the active tab underline, the active filter-tab
underline, and a vocabulary word's due-date label. It is never a button
fill, never a badge background, never a section highlight.

Components never read a raw hex or `colors.light.x` directly — always
`useTheme()`:

```tsx
const { theme } = useTheme();
<View style={{ backgroundColor: theme.bg.surface }} />
```

`useTheme()` (`src/theme/useTheme.ts`) resolves `light`/`sepia`/`dark` from
an explicit stored preference, defaulting to `"system"` (follows
`useColorScheme()`).

## Typography (`src/theme/tokens/typography.ts`)

Three scales, one per family — every token documents its exact source
mockup + CSS selector in a comment. Do not add a new size without a mockup
value to point at.

**Fraunces (`type`)**: `display`(32/600) → `screenTitle`(28/600) →
`heroTitle`(26/600) → `continueTitle`/`wordLemma`(20/600) →
`sectionHeading`(18/600) → `bookTitleLg`(19/600) → `bookTitleMd`(16/600) →
`chapterRowTitle`(15/500, the one medium-weight display token).

**Literata (`readingType`)**: `chapterSubtitle`(13 italic),
`wordPreview`(15 italic), `gloss`(14 italic) — reading-surface chrome only.
The reader's actual paragraph text is generated by
`getReadingTypeScale(scale, lineHeightScale)`, driven by the user's
adjustable font-size/line-height preference (base 18px / 1.7 line-height
at `scale = 1`), not a static token.

**IBM Plex Mono (`monoType`)**: 24 named tokens covering every distinct
size/weight/letter-spacing/case combination used across all seven
mockups (9px–17px, weight 400 or 500) — `eyebrow`, `label`, `meta`,
`statValue`/`statValueLg`/`statValueXl`, `badge`, `dueLabel`, `tag`,
`buttonLabel`, etc. See the file's inline comments for the full list and
each token's source.

## Spacing & layout (`src/theme/tokens/spacing.ts`, `layout.ts`)

4pt-rounded spacing scale derived from real mockup padding/margin/gap
values (each token's comment shows what raw value it was rounded from).

Layout constants: `screenHorizontalMargin` (20px, every screen), 
`coverAspectRatio` (2/3 — **never square, never cropped**),
`coverColumnWidth.{sm,md,lg}` (52/64/104px, the fixed-width column in the
asymmetric grid), `accentLineThickness` (2px, the progress-bar/active-tab
underline weight).

**Hairlines use `StyleSheet.hairlineWidth`, never a numeric literal.**
There are no cards or boxes anywhere in this app — every section/row
boundary is a hairline divider (`Hairline` component) or, for badges,
a 1px `border.strong`/`border.hairline` outline.

## Component kit (`src/components/ui/`)

Only components actually used by the six built screens exist here —
nothing is speculative. Import from the barrel: `import { BookCover,
Hairline } from "@/components/ui"`.

| Component | Notes |
|---|---|
| `BookCover` | **2:3 aspect ratio, always.** Renders `cover_url` via `expo-image`; skeleton while loading; on error/missing, a single neutral-surface fallback with Fraunces title + mono author — **no per-book color**, that idea (borrowed from an earlier art-direction option) was explicitly rejected for not scaling past a handful of books. |
| `Hairline` | The only divider primitive — wraps `StyleSheet.hairlineWidth`. |
| `StatCell` | Mono number + mono label. `bordered` prop switches between book-detail's plain inline stats and profile's bordered 2×2 grid — same component, one prop, not two components. |
| `SectionHeader` | Fraunces title + optional mono "more" link. |
| `ProgressBar` | Hairline track + accent fill — continue-reading %, reader progress line. |
| `FilterTab` | Mono uppercase filter/level tab; active state = accent underline (`accentLineThickness`). Shared by library's level filter and vocabulary's status filter. |
| `LevelBadge` | Bordered mono CEFR tag (`border.strong`, no fill). |
| `Button` | `primary` fills with `text.primary` (ink), **not accent** — matches the mockup's CTA and keeps accent status-only. |
| `TabBarButton` | Custom `tabBarButton` renderer for the bottom tabs — Expo Router's default tab button can't draw the mockup's active-tab underline, so this replaces it. |
| `EmptyState` / `ErrorState` / `LoadingState` / `Skeleton` | Token-driven, Fraunces heading + mono body, no illustrations/emoji. |
| `BottomSheet` | Thin themed wrapper around `@gorhom/bottom-sheet`. |

**Excluded from the barrel, not migrated, do not use:** `Card`,
`CoverageBadge`, `ListItem`, `ProgressRing`, `SegmentedControl`, `Slider`,
`Toast` were deleted — they belonged to the first (rejected) design pass,
referenced token names that no longer exist, and nothing in the current
app imports them. If a future screen genuinely needs one of these shapes,
rebuild it from a mockup, don't resurrect the old file.

## Usage rules

1. **No raw hex or numeric literals in component styles.** Color always
   through `theme.*` (via `useTheme()`); size/spacing always through
   `type.*` / `monoType.*` / `readingType.*` / `spacing.*` /
   `layout.*` from `src/theme/tokens`.
2. **`useTheme()` is the only way to read color** — never `colors.light.x`
   directly; that produces a component blind to sepia/dark.
3. **Mono carries all small UI text.** Don't reach for a system
   sans-serif font family string anywhere in a component.
4. **Accent is status/progress only.** If you're tempted to use `accent`
   for a button fill, a badge background, or "just to add color" —
   don't. Use `text.primary` (ink) for solid fills instead.
5. **Every user-visible string goes through `t()`** —
   `src/i18n/locales/{tr,en}.json`, tr first.
6. **`StyleSheet.create` for structure, dynamic objects for theme color** —
   RN's `StyleSheet.create` can't be theme-reactive at module scope, so
   static layout lives in `StyleSheet.create`, and color is merged in via
   an array: `style={[styles.base, { color: theme.text.primary }]}`.
7. ESLint enforces (1) automatically — `no-restricted-syntax` in
   `.eslintrc.js` rejects raw hex literals and raw
   `fontSize`/`lineHeight`/`letterSpacing`/`padding*`/`margin*`/`gap`
   numbers inside any `StyleSheet.create` call under `app/**` or `src/**`
   (excluding `src/theme/**`, where the literals legitimately live).

### Don't do this

```tsx
// ❌ raw hex, hardcoded font size, not theme-reactive
<Text style={{ color: "#A6572E", fontSize: 14 }}>{title}</Text>

// ❌ accent as decoration, not status
<View style={{ backgroundColor: theme.accent }}><Text>Level B1</Text></View>

// ❌ per-book color fallback (rejected direction)
<View style={{ backgroundColor: palette[hash(slug)] }}>
  <Text>{title.charAt(0)}</Text>
</View>

// ❌ a card/box around a list row
<View style={{ borderRadius: 12, shadowOpacity: 0.1, padding: 16 }}>...</View>
```

```tsx
// ✅
const { theme } = useTheme();
<Text style={[monoType.dueLabel, { color: theme.accent }]}>{dueLabel}</Text>
<BookCover coverUrl={book.coverUrl} title={book.title} author={book.author}
  width={layout.coverColumnWidth.md} />
<Hairline />
```

## Open items for future work

- **Reader screen was not rebuilt this round** — `mockups/reader.html` is
  the approved spec for it, but the horizontal page-turning architecture
  is a separate task. The existing `src/features/reader/**` files were
  only mechanically repaired to compile against the new tokens (old
  layout/behavior kept) — they are not yet mockup-accurate.
- **Sign-in, delete-account, and the source-license sheet** have no
  mockup yet and were only token-repaired, not redesigned.
- **Sepia/dark theme values are derived, not mockup-specified** — no
  mockup shows them. Worth a design pass once real screens exist to
  render against.
- **200-book library scroll performance** was reasoned through
  statically (FlashList, no on-device profiling — this environment has
  no iOS/Android simulator). Worth a real-device check before shipping.
